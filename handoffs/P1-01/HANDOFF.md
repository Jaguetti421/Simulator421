Design decisions within scope:
1. **New records, not edits to the existing sixteen.** TP §8's missing halves could have been bolted onto `ActionRequest`/`ActionResult`. Adding records instead leaves those shapes byte-identical, so the digest change is one explicit event and no packet that already depends on them has to be re-reviewed for a silent field.
2. **The digest change is loud.** `identity.contract.recordsDigest` appears in every run summary, failure bundle and render summary this build produces. It moved from `291f9b94…` to `3fe2ced1…`; old artifacts stay valid records of the surface they were made against.
3. **`AppearanceRecipe` is frozen here, at Jani's direction**, closing the W0-10 finding. The contract carries palette **indices**, not hex strings, so colour choice stays app-side while identity is data. The app kit's slot families are now checked against the contract enums by a test, so the two cannot drift.
4. **Text stays out of the contract.** `ActionFailure` carries an `intentTemplateId`, never a display string (TP §12: display names never serve as identifiers).
5. **The consumer map is name-based on purpose.** A machine could match records structurally, but a person making a contract change greps for the name — so a record only a generic loop covers is exactly the one that will be missed, and the test now says so out loud.
