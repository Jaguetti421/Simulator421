Design decisions within scope:
- **Seeding rule is project-defined and versioned.** There is no external reference for "how to seed sfc32 from a match seed and a label", so `RANDOM_SEEDING_RULE` is a string in the code and in the vectors; changing it requires a new string and regenerated vectors. The *step function* is the published sfc32 and is cross-checked against a third-party implementation — the two claims are kept separate on purpose.
- **Derivation touches no shared state.** A stream is a pure function of (matchSeed, label), so adding a guest or cosmetic stream cannot perturb a core stream — the property in the card is structural, not a test-time accident.
- **Order independence by canonicalization, not by a commutative combiner.** The accumulator sorts by the stable numeric key before folding (TP v1.1 §4 "stable ordering uses numeric IDs"); a commutative XOR/addition combiner would also be order-independent but would lose the swap of two digests between keys. A duplicate key throws rather than overwriting.
- **`nextBelow` is unbiased by rejection**, so a draw may consume more than one word; that is deterministic and reflected in the saved state. `nextChanceMilli(0)`/`(1000)` decide without consuming a word — documented and tested, since it changes stream alignment.
- Labels must be ASCII (the byte reduction is defined for ASCII); non-ASCII throws instead of silently encoding.
